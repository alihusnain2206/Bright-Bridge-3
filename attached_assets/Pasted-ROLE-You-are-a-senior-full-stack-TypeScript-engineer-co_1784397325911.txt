PART 4 — TASK ACTION MODAL 
(THE GLUE)

Create:
src/components/TaskActionModal.tsx

PURPOSE: When a user clicks an 
onboarding task, open the RIGHT 
interaction instead of a bare 
checkbox.

First, add a simple task list UI 
so tasks are clickable:
→ In the People directory row 
  actions, add "Onboarding Tasks" — 
  opens a modal listing that 
  employee's tasks grouped by stage 
  (from GET /api/onboarding-tasks
  ?employeeId=xxx), each with status 
  badge, due date, assigned role, 
  and overdue highlighting (red 
  due date if past due and not 
  completed)
→ Show overall progress bar at top 
  (completed required / total 
  required)

TASK ROUTING — when a task row is 
clicked, open the matching action 
inside the modal:

1. Task name contains "Emergency 
   Contact" → render 
   EmergencyContactForm (Part 2)

2. Task name contains "Upload", 
   "Records", "Identification", 
   "Certification", "Immunization", 
   "Physical", "TB Test" → render 
   EmployeeDocuments upload form 
   (Part 3) with the document type 
   pre-selected where it can be 
   inferred from the task name

3. Task name contains 
   "Acknowledgment", "Acknowledge", 
   "E-Sign", "Handbook", "Policy", 
   "Code of Conduct", "NDA", 
   "Confidentiality" → render an 
   acknowledgment view: task name, 
   a checkbox "I acknowledge I have 
   read and agree", a "Signed by" 
   name input (pre-filled with 
   logged-in user name), and a 
   Confirm button. On confirm: 
   complete the task, log activity 
   with "acknowledged by [name]"

4. Task assignedToRole is "hr", 
   "manager", "it", or "admin" and 
   none of the above matched 
   (verification/assignment style 
   tasks like "I-9 Section 2 
   Verification", "Run Background 
   Check", "Issue Key Card") → 
   render a verification view: 
   task name, optional Notes 
   textarea, and a "Mark as 
   Completed" button

5. Everything else → simple 
   completion view: task name, 
   description, "Mark as Completed" 
   button

All completions go through the 
existing POST /api/onboarding-tasks/
:id/complete endpoint (which already 
handles readiness flags, activity 
logging, and auto-activating the 
employee when all required tasks 
finish). Do not duplicate that 
logic client-side — just call the 
endpoint and refresh.

Non-required tasks also show a 
"Skip" link calling the existing 
skip endpoint.
