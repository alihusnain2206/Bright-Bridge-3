PART 3 — THE TASK ACTION MODAL: 
TWO MODES

MODE A — PENDING TASK (action mode):
Opens the correct interaction by 
task type (routing table in Part 4).

MODE B — COMPLETED TASK (detail/
review mode): EVERY completed task 
row must remain CLICKABLE. Clicking 
opens the modal in review mode 
showing:

→ Green "Completed" header with: 
  completed date, completed by 
  (person name or "System 
  (auto-completed)"), completion 
  method badge (Auto / Manual / 
  Form / Upload / Acknowledged / 
  Verified)
→ WHAT WAS DONE — content depends 
  on how it was completed:
  • Auto tasks: show the actual 
    wizard data that satisfied it 
    in read-only fields (e.g. 
    Personal Information task shows 
    masked SSN ***-**-7890, DOB, 
    address; Federal W-4 shows 
    filing status, dependents; 
    Direct Deposit shows bank name 
    + masked account; Assign 
    Department shows department + 
    manager). Include an "Edit" 
    link where a real edit surface 
    exists (e.g. links to employee 
    edit page) — do not build new 
    edit forms for wizard data in 
    this task.
  • Form tasks (Emergency Contact): 
    show the saved contact(s) 
    read-only + "Edit Contacts" 
    button opening the existing 
    EmergencyContactForm.
  • Upload tasks: show the linked 
    document(s): name, type, upload 
    date, expiry date with color 
    status, Download button, and 
    "Upload Replacement" button 
    (replacement adds a new document 
    version, keeps the old one, 
    updates the link).
  • Acknowledge tasks: show "Signed 
    by [name] on [date]" with the 
    acknowledgment text that was 
    agreed to.
  • Verify tasks: show the 
    verification note and verifier.
→ NOTES section (all tasks, both 
  modes): list of notes with author 
  + timestamp, and an "Add Note" 
  input. Notes can be added even

→ REOPEN: a "Mark as Not Completed" 
  (reopen) button with a confirm 
  step ("This will move the task 
  back to pending. Attached 
  documents and notes are kept."). 
  Calls the reopen endpoint. After 
  reopening, the task returns to 
  the pending list and progress/
  score numbers update.

PART 5 — BEHAVIOR RULES

1. Idempotent completions — 
   completing an already-completed 
   task is a no-op.
2. Reopen keeps history: documents 
   stay linked, notes stay, 
   acknowledgment record stays 
   visible in the detail view 
   labeled "Previous completion".
3. Every complete/reopen/note 
   action logs to 
   people_activity_log.
4. Compliance sync both ways: 
   complete → compliance item 
   completed; reopen → compliance 
   item pending; score recalculated 
   and directory badge reflects it.
5. Employee auto-activation logic 
   unchanged (all required done → 
   active). If a task is REOPENED 
   after the employee became 
   active, do NOT revert the 
   employee to onboarding — instead 
   log activity and let the 
   compliance score reflect the gap.
6. All modals: loading, error, and 
   empty states; masked SSN/account 
   numbers everywhere; TypeScript 
   throughout; existing styling 
   patterns.
