## PART B — CONSOLIDATED DASHBOARD ENDPOINT

New endpoint: GET /api/dashboard/payroll (company derived from session, same pattern as the
existing GET /api/dashboard used by Settings).

It should batch, server-side, the data the future dashboard needs:
- Current pay period (what /rollfi/payperiod resolves)
- Current period details (what /rollfi/payperiod/details returns — payrollLineItems, totals,
  employeeTaxSum, employerTaxSum) — this also yields the authoritative "employees to pay"
  count from payrollLineItems.length
- Pay period history (what /rollfi/payperiod/history returns — needed by Funding Forecast
  and Variance)
- Company tasks / onboarding status (what /rollfi/company-tasks returns)

Response shape suggestion (adjust to fit existing conventions):
{
  payPeriod: {...} | null,
  details: {...} | null,
  history: [...],
  companyTasks: [...],
  employeesToPay: number | null,
  fetchedAt: ISO timestamp,
  errors: { payPeriod?: string, details?: string, history?: string, companyTasks?: string }
}

Requirements:
- **Server-side cache ~60 seconds per company** (in-memory keyed by companyId is fine,
  consistent with existing store.ts patterns). Include fetchedAt so the UI can show
  freshness. Provide a cache-bypass mechanism (?refresh=true) for an explicit refresh action
  later.
- **Partial-failure tolerant**: if one Rollfi call fails, return the others plus the error
  in the errors map — do NOT fail the whole endpoint because one upstream call failed.
- **Company-scoped**: session company only, same guard pattern as /api/dashboard. A user
  must never receive another company's payroll data from cache — cache key MUST include
  companyId.
- Reuse the existing internal functions that the current /rollfi/* routes use to call
  Rollfi — do not duplicate Rollfi request logic. If those routes wrap logic that isn't
  importable, extract the shared logic into a service function both can call (again: no
  behavior change to existing routes).
- Do NOT modify or remove the existing /rollfi/* endpoints — the payroll screens keep using
  them unchanged. This endpoint is additive.
